# C# スクリプトデバッグ（ブレイクポイント）セットアップマニュアル

本プロジェクト（ONEngine）は、C++エンジン内部に Mono を組み込み、C#スクリプトを実行しています。
本ドキュメントでは、VS Code を用いて C# のコードにブレイクポイントを設定し、ステップ実行や変数の確認（デバッグ）を行うためのセットアップ手順を解説します。

---

## 1. 自動セットアップ手順 (推奨)

プロジェクトのルートにある自動セットアップスクリプトを1回実行するだけで、必要な拡張機能のインストール、パス検証、プロジェクトファイルの生成（デバッグ対応PDBの設定含む）が一括で行われます。

1. **PowerShell** を起動します。
2. プロジェクトのルートディレクトリに移動し、以下のコマンドを実行します。
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\SetupEnvironment.ps1
   ```
3. スクリプトの検証結果に従い、処理が完了するのを待ちます。
   * ※ パスに全角文字（日本語など）が含まれている場合は警告が表示されます。その場合は、指示に従ってすべて半角英数字のパス（例: `C:\Develop\ONEngine` など）へプロジェクトフォルダを移動してください。

---

## 2. プロジェクトのビルド

### 2.2 VS Code での C# ビルド方法
C# スクリプトをビルドするために Visual Studio を起動する必要はありません。VS Code のタスク機能を利用して、IDEから直接ビルドすることができます。

1. **ワークスペースを開く**:
   VS Code でプロジェクトのルートディレクトリ（`TD4-2-Clone2`）またはC#プロジェクトフォルダ（`SubProjects/CSharpLibrary`）のいずれかを開きます。
2. **ビルドタスクの実行**:
   * **`Ctrl + Shift + B`** キーを押します。
   * もしくは、上部メニューの **「ターミナル」＞「ビルドタスクの実行 (Run Build Task...)」** をクリックし、`Build C# Library` を選択します。
3. **ビルド完了の確認**:
   実行するとVS Code内の統合ターミナルでビルド処理が走り、C#ライブラリが自動ビルドされて成果物が `Project/Packages/Scripts` ディレクトリへ転送されます。

### 2.3 ビルド構成の選択
デバッグを行うには、エンジンが **`Debug`** または **`Development`** 構成でビルドされている必要があります。
* Visual Studio 上部で構成を **`Debug`** または **`Development`** に設定し、ビルドして実行してください（`Release` 構成ではデバッグ機能は無効になります）。

---

## 3. デバッグの実行手順

デバッグには、**通常アタッチ（推奨）** と、**起動時サスペンドアタッチ** の2つのモードがあります。

### モードA: 通常アタッチ（起動した後に接続する）
デフォルトの起動モードです。ブレイクポイントを使わない時は一時停止をせずに即時起動するため、最も使いやすいモードです。

1. **エンジンの起動**: Visual Studio 等から普通にエンジンを起動します（即時ゲームが開始されます）。
2. **VS Code でアタッチ**:
   * VS Codeで `SubProjects/CSharpLibrary` または C#コードが含まれるディレクトリを開きます。
   * デバッグタブ（`Ctrl + Shift + D`）を開き、構成から **`Mono Attach`** を選択します。
   * **`F5`** を押してデバッグ（アタッチ）を開始します。
3. **デバッグの開始**: これによりアタッチが成功し、ブレイクポイントが有効化（中空ではなく赤丸）されます。コードがその行を通過した際に一時停止します。

---

### モードB: 起動時サスペンドアタッチ（起動の瞬間に停止させる）
ゲームの起動直後（初期化処理や最初の `Start` メソッドなど）でブレイクポイントを止めてデバッグしたい場合に使用します。

1. **起動オプションの追加 (Visual Studio)**:
   * Visual Studio で `ONEngine` プロジェクトのプロパティを開きます。
   * **「構成プロパティ」 ＞ 「デバッグ」** の中の **「コマンド引数」** に **`--wait-dbg`** を指定します。
2. **エンジンの起動**:
   * Visual Studio 等からエンジンを起動します。
   * エンジンは起動直後、**デバッガの接続待ち（サスペンド状態）になり、ゲーム画面が表示されず一時停止（フリーズ）** します。
3. **VS Code でアタッチ**:
   * VS Code でデバッグ画面から **`Mono Attach`** を選択し、**`F5`** を押します。
   * アタッチされた瞬間にエンジンのサスペンド状態が解除され、ゲームの起動処理が動き出します。起動直後のブレイクポイントで正しく停止します。

---

## 4. ホットリロード時の動作と注意点

本エンジンは、起動したままでもC#コードをビルドすると即時反映される「ホットリロード（タイムスタンプ付きDLL）」を採用しています。

### ホットリロード時のブレイクポイント追従について
VS Code デバッガは、ホットリロードによって新しくロードされたアセンブリ（タイムスタンプ付きDLL）へブレイクポイントを自動で貼り直すことができません。
* **注意点**: コードを変更して再ビルド（ホットリロード）した後は、一度VS Code側のデバッガを切断（停止ボタン）し、**再度 `F5`（Mono Attach）でアタッチし直して**ください。アタッチし直すことで、新しくロードされたアセンブリに対して再びブレイクポイントがバインドされます。

## 5. コア機能の動作確認 (SerializeField & ホットリロード)

ブレイクポイントの有効化などの変更を行った後、既存の主要機能（`SerializeField` によるシリアライズ値の読み込み、および `ホットリロード`）が正常に機能しているかをテスト・検証するためのツールが提供されています。

### 5.1 検証スクリプトの実行方法
PowerShellを開き、プロジェクトのルートディレクトリで以下のコマンドを実行します。
```powershell
powershell -ExecutionPolicy Bypass -File .\VerifyFeatures.ps1
```

### 5.2 検証内容
1. **SerializeField の自動検証**:
   * テストシーン（`InheritSerializeFieldTest`）を自動的に実行し、値のデシリアライズ（C++側からC#側へのデータロード）が正しく行われたかを検証します。
   * 問題がなければ、画面に `【合格】SerializeField の親子継承デシリアライズは正常に動作しています。` と表示されます。
2. **ホットリロードの自動/手動ハイブリッド検証**:
   * スクリプトが検証用のログ出力コード（`=== HOT RELOAD SUCCESS ===`）を C# コードに一時的に挿入し、自動的に `dotnet build` を実行してDLLをコンパイルします。
   * 起動しているゲームエンジンのログ画面（ImGuiのコンソールウィンドウなど）に `=== HOT RELOAD SUCCESS ===` が毎フレーム出力されていることを目視確認します。
   * 検証が終了すると、書き換えられたC#コードは自動的に元の状態にロールバックされます。
